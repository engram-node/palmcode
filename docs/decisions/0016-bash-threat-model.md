# 0016 Bash threat model
Status: accepted. Applies to the bash tool on Android and the host executor.
Context: bash runs real processes (busybox, ripgrep, git) as the app's own UID. Model output, repository files and tool output are untrusted input; prompt injection is expected.
Decision: permission prompts and command classification are the security boundary. The bash tool is NOT a sandbox and must never be described as one in the UI or docs.
What a command can do: read and write any file the app UID can access, including the app database (session history), spill files, other workspaces and the userland; make network connections; spawn background processes. It cannot read the API key: the key is stored encrypted under the Android Keystore, decrypted only in the app process, and never placed in a child environment.
Mitigations: (1) conservative classifier: small allowlist with per-command flag grammars, everything else asks; (2) path policy: operands must resolve canonically inside the workspace, secret files ask, outside paths are denied; (3) network commands always ask, and git runs with config overrides that neutralise repo-defined hooks, fsmonitor, pagers, external diff and credential helpers; (4) workspace trust: untrusted workspaces ignore project config and cannot grant permissions, all git commands ask; (5) sanitized child environment, stdin closed, per-call timeout, process-group kill, subreaper sweep and pidfile sweep at start; (6) output caps and spill limits.
Accepted risks: an approved command can do anything the UID can do; the classifier can have gaps; same-UID access to app data is not prevented. Auto-approve mode widens this and must be visibly flagged.
Rejected alternatives: isolatedProcess services (no access to the workspace or network); proot (needs legacy targetSdk and is still the same UID); seccomp filters (cannot inspect path arguments, so they cannot confine paths); Landlock (availability on target kernels unverified; revisit after a feasibility check).
Revisit when: Landlock is confirmed available, or a toolchain pack (proot rootfs) is added.
